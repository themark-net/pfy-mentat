## CLI exit contract (`./pfy decision route`)

| Exit | Verdict | Meaning |
|-----:|---------|---------|
| **0** | ready | Margin at/above gate; callers may act on `choice` |
| **3** | escalate | Conf low — **valid outcome**, not a tool failure; no silent auto-act |
| **1** | fail | Broken / unexpected error |
| **2** | usage | Bad argv |

## Headless Build wrap

```bash
./pfy build -p "Implement …" --cwd /path/to/worktree
# dry-run (no grok exec, still writes receipt):
./pfy build -p "…" --dry-run
```

Always uses `--output-format plain` (not `text`). Receipt: `pipelines/dogfood/build/<ts>/receipt.jsonl` with `preamble_tokens_est` (chars/4) separate from the task prompt, and `skills_bundle_tokens_est` (same method) for the skills tree the child home exposes. Default preamble is trimmed (jev gate, route exits, receipt path, skill pointer). The trimmed child GROK_HOME holds a real-file pointer at `skills/pfy-jev-decision/SKILL.md`, a byte copy of `auth.json`, and `bundled/` as a real directory of byte copies (not file symlinks, not one directory symlink, and not the user skills tree; dest copies are chmod `a-w`). `PFY_BUILD_FULL_PREAMBLE=1` inlines the jev skill bodies and keeps the real GROK_HOME. `PFY_BUILD_FULL_SKILLS=1` restores pointer-only isolation and does not keep the real GROK_HOME. A live run with `bundled/` missing exits 1, receipt reason `bundled_missing`.
