# Autonomous decisions: 2026-10-19 (integrations drop-ins H1 Harness² local, H2 skill discovery)

One line per choice. Format: choice | alternatives | why.

1. H1 targets the 48-case decision set (`data/decision-gates/laya-trial.cases.v0.json`) | JobBench via `harness2-setup jb` | local, labeled, no Hugging Face download and no Vertex judge, deterministic scoring against our own labels, and it is the set `qwen3.6:35b` was picked on (38/48).
2. H1 drives the upstream core loop (`core.recursion.run_parallel`) with our own adapter, preflight and setup steps | `harness2`, `harness2-check` and `harness2-setup` CLIs | the CLIs only take `jb|lab|wb`, `preflight.check()` raises `KeyError` for any other adapter, and setup clones job-bench-eval and pulls from Hugging Face.
3. H1 serves `qwen3.6:35b` from its own `llama-server` (`llamacpp-nommap` lane, `-c 32768`) | Ollama with its default context | OpenCode's prompt does not fit 8192 tokens, Ollama's OpenAI endpoint takes no `num_ctx`, and changing Ollama's config is a system change; an own process can be stopped at exit without touching anyone else's model.
4. H1 drops the `[render]` extra | install it and allow pypi for its wheels | openpyxl and python-pptx only render JobBench and WorkBuddy outputs; pypi stays allowed only for the setuptools/wheel build backend.
5. H1 improvement gate is at least +2 held-out cases with the base scored twice, temperature 0 and seed 230 | at least baseline | 16 held-out cases make a 1-case gain indistinguishable from noise.
6. H1 treats AGENTS.md-derived guardrails as read-only for proposals | allow edits and let Reviewer catch them | hard rules change only by Mark's hand.
7. H2 parses Monid endpoints recursively and derives id and kind | read them from `meta` | `meta` has no provider, id or kind, and 481 of 719 endpoints sit one level deeper.
8. Both drop-ins copy themselves from `origin/main` and base their worktrees there | copy from `origin/bot/integrations-h2-monid` | Build should run what was merged, not a branch that can still move.
9. H1 chains the train tasks: task t+1 starts from task t's `agg1` if `agg1` scored at least `base1` on task t's batch (and parse_ok did not drop), else from the same harness; each task adds one count-only lesson to the upstream library; the final chain state is the one scored on the 16 held-out cases and proposed | each task starts from base and the best single `agg1` is picked; or the last `agg1` unconditionally | chaining is how the method compounds, the non-regression check stops one bad batch from carrying forward, and one final harness keeps the held-out gate a single comparison against base.
10. H1 uses nimo's existing uv-managed CPython 3.12.12 read-only with `UV_PYTHON_DOWNLOADS=never` | let uv download Python (adds `releases.astral.sh` or a GitHub release host) | nimo's system python3 is 3.14, outside harness2's `>=3.12,<3.14`; a read-only interpreter means no extra host and no HOME write; if it is missing, the step blocks instead of widening the network.
11. H1 bwrap hides the real HOME with `--tmpfs "$HOME"` and binds back only `$W/tmp/harness2` (read-only), the writable run dirs and that interpreter dir | a read-only `/` with HOME visible | an agent could otherwise read SSH keys or gh tokens and copy them into a proposal branch.
12. H2 relies on a 2-minute `keep_alive` on its own Ollama requests instead of `ollama stop` at exit | stop the model at exit | a stop at exit races with Mark loading the same model.
13. H1 library lessons carry counts only (for example `base1 5/8, agg1 6/8`) | upstream's contrast evidence (selector-written cue, lesson and evidence comparing what the chosen and rejected runs did on specific cases) | ours is weaker evidence for the next editor, but per-case contrasts would carry case content and outcomes across tasks, and the 48-case labels must never reach an editor; the cue and lesson text still come from the editor's own notes.
14. H1 executors see opaque case ids (`t01`..`t48`, seed-230 shuffle; map kept host-side in `$W/tmp/host-only`, never bound) | the real ids | 19 of 48 real ids contain their own label word, so they leak the answer and an editor could overfit to it on train and held-out alike. Follow-up, not fixed here: the existing trial.py baselines (including qwen3.6:35b's 38/48) showed models the same real ids, so those scores may be inflated; rescore them with opaque ids in a separate change. Two more leaks found at `ef79300`: the source criteria key order puts the label first in 24 of 48 cases (H1 now shuffles keys per case with seed 230; the trial.py rescore must shuffle too), and a case's own label appears in its instructions or state in 11 of 48 cases (Reviewer's count; mild and content-level, versus 12% for other keys; not changed here). The id map, gold labels and all per-case and held-out scores stay in a host-only dir that is never bound into the sandbox.
15. H1 sandbox binds only `/usr`, `/etc`, `$W/tmp/harness2` read-only, the two writable run dirs (`$W/tmp/harness2-runs`, or `$W/tmp/heldout-runs` for held-out executor calls, and `$W/tmp/state`, whose `opencode.json` and `bin/` are bound back read-only) and the interpreter root (merged-usr symlinks for the rest); the rest of the worktree is absent inside | `--ro-bind / /` plus tmpfs over known socket dirs | a read-only bind does not block `connect()`, and nimo has sockets outside /run (`/var/snap/maas/.../.pebble.socket`); not binding them is simpler than chasing each one.
16. H1 socket preflight prunes directories the sandbox user cannot search (`find "$m" -xdev \( -path /proc -o -path /sys \) -prune -o -type d ! -executable -prune -o -type s -print`) and keeps every other nonzero rc or timeout as BLOCKED | treat rc 1 as fine, or drop `Permission denied` lines from stderr | a unix socket under an unsearchable dir cannot be reached (`connect()` needs search permission on the path), so pruning loses nothing, while ignoring rc 1 or filtering stderr would also hide real errors; the unpruned scan exits 1 on `/etc/ssl/private` (root 0700) and blocked every launch at `57bbed9`.
17. H1 held-out executor calls use their own runs dir `$W/tmp/heldout-runs`, bound only for those calls and moved to `$W/tmp/host-only/heldout/` after scoring | keep held-out workspaces in `$W/tmp/harness2-runs` | that dir is bound read-write into every training editor call and OpenCode's bash path guard covers only some commands, so editors could read held-out inputs and answers (no labels, but it undercuts held-out isolation); Tester's finding at `57bbed9`.
