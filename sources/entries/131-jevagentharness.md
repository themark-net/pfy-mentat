### Entry 131: JevAgentHarness (`jah`) — per-step strong/fast router for coding agents, with a local System-One decision lane

- **URL**: https://github.com/JevAgentHarness/JevAgentHarness (MIT, Python; 24 stars at this read; no release, `pyproject` version 0.1.0; checked at commit `f2932199e1ef`, 2026-10-16). Paper: https://arxiv.org/abs/2610.21412
- **Date**: 2026-10-19 (daily X intake, window 2026-10-18T00:36Z to 2026-10-20T00:36Z)
- **Source / Poster**: @alex_verem, https://x.com/alex_verem/status/2111850301129097464 (paper post; the repo is linked from the paper and README)
- **Summary / Key Claims** (upstream README at `f2932199e1ef`): a local OpenAI-compatible proxy that sits between an unmodified agent harness and its model provider. For each agent step it asks a decision model "is the next step `routine` or `hard`?" and sends routine steps to a fast model and hard ones to a strong model. The first step(s) and the "task is done" answer always go to the strong model (`first_steps_strong`, `verify_finish`), and any decision error falls back to strong (`on_error: strong`). Every step is logged (tier, tokens, cost, latency; `jah report`). On 74 held-out Terminal-Bench 2.0 tasks, three harnesses stayed within 3 points of strong-only success while spending 28-64% less on LLM calls. Decision backends: `{type: rules}` (no model), hosted Jev (TypeSafe/OpenRouter, paid), or **`{type: jev, provider: local, base_url, model}`: any server that speaks the Jev System-One wire format (`POST /v1/systemone`)**.
- **Why it matters here**: the local lane speaks the same `POST /v1/systemone` wire that Laya's `laya-serve` (Entry 086) serves and that ADR-0016's `typesafe` lane expects, so this is a ready-made consumer of the decision slot we can't fill with a paid key. It also gives the bots a concrete, measurable way to spend fewer strong-model calls on routine steps (e.g. a strong local tier and a fast small local tier on Ollama). This differs from Entry 122 (llm-router routes whole prompts; this routes each agent step) and Entry 123 (HarnessRouter fronts harnesses, not models). **Possible eval-auto trial**: shadow mode against the current ADR-0016 lane (see Findings).
- **Fit on nimo**: Yes, as a venv under `~/DEVELOP/pfy-mentat/tmp/jevagentharness/` (deps `aiohttp`, `pyyaml`; 11 packages in the venv). Both tiers can point at Ollama's OpenAI endpoint on loopback; no GPU or key is needed for the proxy itself. The published AgentDecision-4B/0.8B decision models are **CC BY-NC 4.0** (fine for Mark's own use, not for anything sold, e.g. the AI-box offer).
- **Verified on the Grok Bot box** (clone at `f2932199e1ef`, `python3 -m venv .venv && .venv/bin/pip install .`, `jah --version` 0.1.0; bubblewrap 0.12.0, no network, temp HOME): smoke PASS. Two `jah serve` runs against a stub upstream on loopback, four steps each. Rules backend routed strong/fast/strong/strong with reasons `first_steps`, `routine`, `hard` (a traceback is an error signal), `finish_check` (the fast tier's text answer was redone by the strong tier). Local Jev backend sent `POST /v1/systemone` with `model: agentdecision-4b` and options `hard`/`routine`, routed strong/fast/strong on p(hard), and an HTTP 400 from the decision server fell back to strong as `decision_error`. No `Authorization` header reached any stub, the step logs held no prompt text, temp HOME and the watched real-HOME dir (`~/.jah`) unchanged.
- **Findings**:
  - **Repeat detection is real**: in a first stub run, identical tool calls (`ls` three times) were routed strong as `repeated_action` before the error signal was even read. Good for looping agents, but a fixture with repeated commands won't measure the error rule.
  - The finish check costs a second upstream call per final answer (`call_tiers` `[fast, strong]`), so savings on short tasks are smaller than the headline.
  - With no decision key, every step falls back to strong and logs `decision_error`: the safe direction, but a silent zero-savings run. `jah report` or the step log has to be checked after any trial.
  - Eval-auto shape: shadow mode with Laya (086) or AgentDecision-4B served locally as the decision model, both tiers on Ollama (`qwen3.6:35b` strong, a small model fast), compared with the ADR-0016 lane (CUA-S1-FORMS primary local) on the 48-case decision benchmark. Measure the share of steps moved to fast and the success delta; no change to the live lane.

- **How this fails / how we recover**:

| Risk | How it fails | Recovery |
|------|----------------|----------|
| Silent zero savings | Decision model down; every step logs `decision_error` and goes strong | Read `jah report`/`steps.jsonl` after each run; alert on a `decision_error` share above a few percent |
| Fast tier quality | Routine steps done badly by a small local model | Shadow mode first; keep `first_steps_strong` and `verify_finish` on |
| Wire drift vs Laya/ADR-0016 | `/v1/systemone` field differs from what the local server returns | Diff one response against the ADR-0016 parser; the smoke pins the request shape it saw |
| Non-commercial weights | AgentDecision models used in a paid offer | Keep them on Mark's own work; use rules or Laya for anything sold |
| Prompt text in logs | A later version logs states | The smoke FAILs if the task text shows up in the logs |
