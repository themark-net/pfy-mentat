### Entry 102: Agent Substrate: Kubernetes runtime that shelves idle agent actors (gVisor checkpoint/restore) onto fewer warm worker pods

- **URL**: https://github.com/agent-substrate/substrate (Apache-2.0, Go, about 4.6k stars at this read, release `v0.4.0` published 2026-10-07 PT; read at `769fd32630aa47bd6d7050b39e1aa0804a8622dc`, 2026-10-08)
- **Date**: 2026-10-08 (direct request from Mark, not the daily X intake)
- **Source / Poster**: Mark (direct request). Upstream announcement context: Google Agent Executor (https://github.com/google/ax) and kagent (https://github.com/kagent-dev/kagent) list it as their runtime.
- **Summary / Key Claims** (upstream README and `docs/architecture.md`, not verified by us): A pre-1.0 runtime that maps many mostly idle "actors" (agents, MCP servers, sandboxes) onto a smaller pool of warm Kubernetes worker pods. An idle actor is suspended to a snapshot in object storage and its worker is freed; a request through the Envoy router (`ate-target-actor` header) resumes it on any free worker. Claims sub-500ms resume, 500+ suspend/resume activations per second, 10x density over plain containers, and a demo of about 250 stateful actors on 8 pods. Sandbox classes are gVisor (default) and micro-VM (Kata guest on Cloud Hypervisor, needs `/dev/kvm`). Control plane is `ate-api-server` (gRPC, PostgreSQL state store), `atecontroller` (WorkerPool CRD), `atelet` (node DaemonSet that moves snapshots) and `ateom-gvisor` / `ateom-microvm` (herder inside each worker pod). `docs/architecture.md` itself says "Much of this architecture is aspirational, and is not yet implemented!"; the roadmap lists incremental snapshots, compression-style storage tiering and autoscaling as not done.
- **Fit on nimo**: Whole-thing fit is catalog-only. It is built for cluster-scale multiplexing, and actors must be HTTP services reached through its router. nimo is one 128 GB Strix Halo box whose memory budget is shared with the GPU. The shelving mechanism underneath it is the interesting part; see the next section.
- **Local shelving angle** (Mark's ask: single-node minikube on nimo, or a lighter path):
  - **How suspend/resume is implemented**: gVisor's own checkpoint/restore, not CRIU. `cmd/ateom-gvisor/runsc.go` shells out to `runsc checkpoint -image-path ...` (`cmdCheckpoint`), `runsc restore` (`restoreArgs`), plus `runsc fscheckpoint` for filesystem-only (`Data`-scope) snapshots and `runsc pause` / `resume`. Containers are started with `-allow-connected-on-save` so open sockets do not block a save (`docs/architecture.md`, "Lifecycle Management"). `atelet` then streams the image to S3 or GCS (`docs/architecture.md`, "Storage Mover"); on kind that is an in-cluster rustfs bucket (`manifests/ate-install/kind/kustomization.yaml`). Snapshots are pinned to the runsc build that wrote them (`internal/proto/ateompb/ateom.proto`, `RestoreWorkload`). The micro-VM class uses Cloud Hypervisor memory snapshots restored with `userfaultfd` demand paging (`docs/architecture.md`, "Sandbox Classes").
  - **Single node, and minikube specifically**: Single node is the documented dev path and the CI path, but on **kind**, not minikube. `hack/create-kind-cluster.sh` builds a one-node kind cluster, and `.github/workflows/pr-workflow.yaml` (`e2e-test`) brings up the full stack, both sandbox classes, the counter demo and the e2e suites (many of which suspend and resume actors, see `internal/e2e/suites/`) on one `ubuntu-latest` runner. A `git grep` for minikube, k3s and k3d in the repo finds nothing, so minikube is unsupported and untested upstream. What the kind script adds that minikube would need by hand: feature gates `ClusterTrustBundle`, `ClusterTrustBundleProjection`, `PodCertificateRequest` and runtime-config `certificates.k8s.io/v1beta1` (for `cmd/podcertcontroller`); `net.ipv4.conf.all.proxy_arp=1` on the node for gVisor pod networking; a local registry on `localhost:5001` wired into the node's containerd, which `hack/install-ate-kind.sh` assumes via `KO_DOCKER_REPO`. Kubernetes support is "latest stable and previous minor" (README), and `go.mod` is on `k8s.io/api v0.37.0`.
  - **Which minikube driver and the gvisor addon**: Do not use `minikube addons enable gvisor`. Substrate never sets `runtimeClassName` (no RuntimeClass reference outside the threat model). Worker pods run under the normal runc runtime, unprivileged but with 13 added capabilities (SYS_ADMIN, SYS_PTRACE, NET_ADMIN and others), seccomp and AppArmor Unconfined, and run as uid 0 (`cmd/atecontroller/internal/controllers/workerpool_apply.go`, `ateomGvisorCapabilities` and `ateomSecurityContext`). `atelet` downloads its own pinned runsc build (`manifests/ate-install/sandboxconfig-gvisor.yaml`, nightly 2026-09-02, sha256 `d547d814...d06f`). Putting workers under the addon's RuntimeClass would nest runsc inside runsc. `--container-runtime=containerd` is fine (kind uses containerd too). The closest match to the tested kind setup is `--driver=docker` (Kubernetes node in a container), which needs Docker or Podman on the host. `kvm2` needs libvirt (a system package) and `none` needs root, so both are out under nimo's rules.
  - **Minimum prerequisites, root and kernel features**: Go, kubectl, Docker (rootful; `docs/dev/microvm-local.md` says the KVM probe fails on rootless Docker), plus kind and ko, which the repo runs through `hack/run-tool.sh`. Linux with cgroup v2 (`internal/ateomcgroup/ateomcgroup.go` errors without a `0::` cgroup line). x86_64 or arm64 runsc assets. `/dev/kvm` only for the micro-VM class. The host user needs Docker access, which is root-equivalent. Nothing in the stack needs host sudo once Docker exists, but on a box without Docker, installing it is a system install.
  - **Resource footprint**: Unmeasured by us. The kind config says the install pulls about 570 MB of third-party images (postgres, prometheus, otel collector, rustfs, envoy, jaeger). Explicit requests we read: postgres 1 GiB request and 2 GiB limit (`manifests/ate-install/postgres/postgres.yaml`), atelet 128 MiB, atenet-egress 512 MiB (768 MiB limit), prometheus 128 MiB (512 MiB limit); the API server, controller, router, rustfs and otel set none. The counter demo adds a WorkerPool of 3 workers at 1 GiB each (`demos/counter/counter.yaml.tmpl`). Upstream CI fits all of it on one `ubuntu-latest` runner. Our estimate, unverified: a minikube profile capped at 6 CPUs and 12 GiB should hold the stack plus a small pool, and that 12 GiB comes out of the same pool nimo's GPU uses.
  - **Does suspend/resume work there**: On single-node kind, yes per upstream CI (counter demo plus e2e suites). On minikube, unverified, since nobody upstream runs it. We expect the docker driver to behave like kind once the three gaps above are patched, but that is an inference.
  - **Standalone shelving, the lighter path**: The Substrate pieces are not usable alone. `ateom-gvisor` is a gRPC service driven by `atelet`, which is driven by `ate-api-server` and PostgreSQL. The underlying mechanism is, though. Box-only smoke on the Grok Bot box (no sudo, no system packages; kernel 6.12, cgroup v2; runsc `release-20260824.0-120` from the same nightly tarball Substrate pins, sha256 matched): `runsc --rootless ... do` runs; `runsc --rootless checkpoint` works but `restore` refuses ("Rootless mode not supported with \"restore\""). Inside an unprivileged user namespace (`unshare -Urm`, not sudo), the full cycle works: a shell counter loop at tick 6 was checkpointed and restored, and it continued at tick 7 (in-memory state kept), with restore taking about 110 ms. A Python process holding 512 MiB of random bytes took 0.76 s to checkpoint into a 516 MB image (about the size of resident memory, no compression), was killed (memory freed), and was restored in 0.21 s, then went on counting from tick 15 with the same in-memory values (we did not re-hash the full 512 MiB buffer after restore). All runs used `--network=none` and the host root mounted read-only. No receipts committed.
  - **Limits of the lighter path** (some unverified): Only processes started under runsc can be shelved, so an already-running host Build session cannot be frozen after the fact. Snapshot size is about equal to resident memory, so shelving 20 GB means writing 20 GB to disk. Live TCP to a model API will probably not survive restore; the agent has to reconnect (unverified; Substrate's `-allow-connected-on-save` lets the save run, but it does not keep the peer alive). Anything using the GPU cannot be shelved this way. gVisor's GPU proxy targets NVIDIA (`cmd/ateom-gvisor/internal/cdiinject/inject.go` mentions nvproxy), and we found nothing for AMD/ROCm (unverified). Images are tied to the runsc build. Ubuntu 24.04+ hosts may block unprivileged user namespaces through AppArmor (`kernel.apparmor_restrict_unprivileged_userns`), which would make the no-sudo path fail on nimo (unverified for nimo).
  - **Verdict**: **A lighter local path worth an eval.** Running the whole of Agent Substrate on minikube is technically plausible but is catalog-only for now, since it is unsupported upstream, needs Docker plus about 12 GiB and three manual patches, and only shelves HTTP actors behind its router. The shelving primitive it uses, gVisor `runsc checkpoint/restore`, already worked without sudo on the box, and it is the piece that could free RAM for big local models. Eval that first; try the minikube Substrate run only if Mark wants its router and multiplexing on top.
  - **Proposed eval plan (not executed on nimo; each stage needs Mark's go)**:
    1. Read-only preflight on nimo: `uname -r`, `stat -fc %T /sys/fs/cgroup` (want `cgroup2fs`), `sysctl kernel.apparmor_restrict_unprivileged_userns`, `unshare -Ur true`, and whether `docker` or `podman` already exists.
    2. Stage A, runsc direct (no install outside DEVELOP): fetch the pinned tarball into `~/DEVELOP/pfy-mentat/tmp/runsc/`, check the sha256, and repeat the box smoke under `unshare -Urm` with a 1 GiB, then 8 GiB, process. Record checkpoint and restore wall time, image size, and the change in `free -g` while shelved. Then shelve a small idle agent sandbox (for example an OpenCode worker started under runsc with networking on) and check it reconnects after restore. Pass bar: memory returns while shelved, the process continues after restore, and it does not lock nimo.
    3. Stage B, minikube (only if Docker or Podman is already there, or Mark approves installing it): `minikube start -p ate --driver=docker --container-runtime=containerd --cpus=6 --memory=12g --feature-gates=ClusterTrustBundle=true,ClusterTrustBundleProjection=true,PodCertificateRequest=true --extra-config=apiserver.runtime-config=certificates.k8s.io/v1beta1=true`, then `minikube -p ate ssh -- sudo sysctl -w net.ipv4.conf.all.proxy_arp=1` (sudo inside the node container, not on nimo), a registry via `minikube addons enable registry` with `KO_DOCKER_REPO` pointed at it, then `KUBECTL_CONTEXT=ate hack/install-ate-kind.sh --deploy-ate-system --credential-provider='{"name":"k8s.io"}'` and `--deploy-demo-counter`. Pass bar: the counter survives `kubectl ate suspend actor` and resume with both counters continuing. Tear down with `minikube delete -p ate`. Do not enable the gvisor addon.
- **Why it matters here**: nimo's real constraint is memory shared between big local models and everything else (Entries 090-092 set an 85 GB ceiling). Being able to park idle agent sandboxes or long Build sessions to disk and get them back in well under a second would let a big model load without killing that work. This is the first catalog item whose core is exactly that, and its mechanism can be tried without Kubernetes.

| Risk | How it fails | Recovery |
|------|----------------|----------|
| Pre-1.0 churn | APIs, install flags or the pinned runsc change between releases (v0.2 to v0.4 shipped in two weeks) | Pin a Substrate commit and the SandboxConfig tarball sha256; re-read the release notes before any rerun |
| minikube drift from kind | Missing feature gate, proxy ARP or registry wiring leaves pods stuck or workers never ready | Fall back to the documented kind path, or stop at Stage A; record which gap failed |
| Userns blocked on nimo | AppArmor userns restriction makes `unshare -Urm` fail, so runsc restore needs root | Stop and ask Mark; do not add sudo or change sysctls without his go |
| Disk and memory spike | Shelving a large process writes an image about the size of its RAM; checkpointing during a model load pushes nimo past its budget | Start at 1 GiB, shelve before a model load, never during one; keep images under `tmp/` and delete after |
| Broken connections after restore | Agent's open HTTPS to the model API dies on restore and the session errors out | Test with a client that retries; treat no-reconnect as a FAIL for that workload, not for the mechanism |
| Hype numbers | Sub-500ms and 500 activations per second do not reproduce locally | Only our own nimo receipts count |
