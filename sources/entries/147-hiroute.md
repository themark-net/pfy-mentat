- **Summary / Key Claims** (upstream README; their claims except where marked verified): a local model router for agent clients such as Codex, Claude Code, Qoder, Pi and DeepSeek Harness. A difficulty-routing plan judges each new user message and sends routine work (reading code, gathering facts) to an economical model while design decisions and hard fixes stay on the primary model; tool calls within a turn keep that turn's decision so the context prefix stays cacheable. Subscriptions, API keys and local models are managed in one place, each session shows which model ran with usage and cost, and "decision models" (the judge) can be custom extensions. Runs as a macOS Desktop app or a Linux headless CLI and daemon.
- **Why it matters here**: Mark's money rule says Grok Build and SuperGrok cost must earn their keep, and pfy-mentat's plan is Grok Build for pace, then local models when rate limits bite. A per-message router in front of the agent client is the mechanism for that split (hard turns to Grok, routine turns to a local model on nimo), with per-session receipts of which model ran. It overlaps our own routing work (Entry 123 HarnessRouter, atg-framework), so the trial is a comparison, not an adoption.
- **Fit on nimo**: Yes for the daemon, verified: x86_64 Linux binaries, no GPU. Staged at `~/DEVELOP/pfy-mentat/tmp/hiroute` (archive, manifest, installer; digests checked); the smoke installs only into a throwaway temp HOME and PASSes on nimo. - **Verified on the Grok Bot box and on nimo** (bubblewrap with no network; HOME, XDG_* and TMPDIR in a temp dir): smoke PASS on both. `standalone.py install --manifest --archive --console-mode off` works offline and reports `{"installed": true, "version": "0.3.1"}`; every path in its marker is under the temp HOME. `hiroute service run` reaches local control within about a second; `service status` shows `local_control_ready: true` (manager systemd-user, not active); `system status` shows `daemon: role_all`, `gateway: ready`, `local_control: v2.0:authenticated`; `gateway show` is ready on `127.0.0.1:<auto port>`. With no source, route or grant, `GET /v1/models` answers 503 `GATEWAY_PUBLICATION_UNAVAILABLE` and `POST /v1/chat/completions` 401 `GATEWAY_GRANT_UNAUTHORIZED`, so it fails closed. `schema list` exposes 51 commands including `routing.preview`, `routing.apply` and `decision.services.test`. The daemon exits on SIGTERM.
- **Findings**:
  - **The installer writes into the agent skill dirs and systemd.** Into HOME it puts `~/.local/bin/hiroute{,d}` (symlinks), `~/.local/lib/hiroute/<ver>`, `~/.local/share/hiroute/`, a user unit `~/.config/systemd/user/ai.hiroute.cli.service`, and a `hiroute-management` skill into both `~/.agents/skills/` and `~/.claude/skills/`, then runs `systemctl --user daemon-reload` (failed harmlessly in the sandbox: "Failed to connect to user scope bus"). Never run it against Mark's real HOME; the smoke watches all of those paths.
  - **No run without install.** `hirouted` from the unpacked tarball exits "standalone installation marker is unavailable", and `hiroute service run` says "standalone installation is unavailable". A read-only installed HOME with a temp state dir fails "standalone proxy environment is unavailable", so each smoke run installs into its own temp HOME (about 177 MB).
  - It bundles CLIProxyAPI (`libexec/cliproxyapi`, version `8.0.4-hiroute.4`, sha256 pinned in the manifest) for subscription proxying; the manifest marks the build `"distribution": "integration-candidate"`. Some CLI messages are Chinese only.
  - The decision-model example in its docs is a hosted Alibaba Bailian endpoint with a Bearer secret registered through `protected-input`; a local decision model is not shown and is the first thing a trial must check.
