### Entry 108: cass-memory (`cm`) — procedural cross-agent memory: a scored playbook of rules built from agent session history

- **URL**: https://github.com/Dicklesworthstone/cass_memory_system (MIT with an OpenAI/Anthropic rider, so GitHub shows the license as NOASSERTION; TypeScript on Bun, 446 stars at this read, release v0.5.0 with single-file binaries; checked commit `229a312b696a`)
- **Date**: 2026-10-10 (daily X intake)
- **Source / Poster**: @DanKornas, https://x.com/DanKornas/status/2108727726504808734
- **Summary / Key Claims** (upstream README and `cm --help`): "Procedural memory for AI coding agents." `cm context "<task>" --json` returns relevant rules, anti-patterns and history snippets for a task; rules live in a playbook (`~/.cass-memory/playbook.yaml`, plus an optional repo-level `.cass/`) with helpful/harmful feedback (`cm mark`), confidence decay (90-day half-life), and deprecation after repeated harmful marks. Session history comes from a separate tool, `cass` (coding_agent_session_search, installed separately), across Claude Code, Codex, Cursor and others. `cm reflect`/`cm diary` extract rules from sessions with an LLM (providers in the source: anthropic, openai, google, ollama, bedrock); with no key it says it degrades to deterministic reflection and playbook-only scoring. Embeddings are local xenova WASM (`Xenova/all-MiniLM-L6-v2`, downloaded once by `cm doctor --fix`) or Ollama `/api/embed`. Also `cm hook` (background auto-reflection on finished agent sessions), `cm validate`, `cm audit`, `cm update`. Default config is `provider: anthropic` with a $1/day budget.
