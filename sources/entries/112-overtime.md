### Entry 112: Overtime — persistent coding agents that keep working across sessions, driven over ACP

- **URL**: https://github.com/ukanwat/overtime (MIT, TypeScript, 392 stars at this read, "status: early"; npm `@ukanwat/overtime` 0.5.3 on `latest`, while GitHub shows release v0.5.9 published 2026-10-12)
- **Date**: 2026-10-12 (daily X intake)
- **Source / Poster**: @DanKornas, https://x.com/DanKornas/status/2109565724641391044
- **Summary / Key Claims** (upstream README, `overtime --help`, `dist/acp/backends.js` in 0.5.3): "Give a coding agent a brief, not a chat, and it works on its own across sessions." Each agent is a folder `~/overtime/agents/<name>/` with `AGENT.md` (job, rules, a settings block), `INDEX.md` (its own map of the folder) and `.overtime/` (settings, state, messages). A detached daemon (`overtimed`) wakes agents on a schedule or on "watch" scripts it runs without the model, keeps a daily dollar budget and token budget per agent, and marks protected paths read-only. Overtime has "no model and no agent loop of its own"; it drives coding agents over the Agent Client Protocol. Built-in backends are `claude` (bundled `claude-agent-acp`, uses a Claude Code login), `codex`, `gemini` and `opencode`; "any other ACP agent can be added under customBackends in settings.json" (`~/overtime/settings.json`, `{command, args}`). Non-interactive CLI: `new`, `ls`, `send`, `messages`, `answer`, `stop|start|wake`, `settings`, `set`, `models`, `archive`, `daemon [stop|install|uninstall]`, `acp`.
- **Why it matters here**: Mark wants long unattended Build runs and finds Build needs babysitting. Overtime's model (an agent is a folder that outlives sessions, wakes itself, budgets itself, asks only real decisions as numbered options) is the closest open match yet to that wish, and to our orchestrator-in-worktree lane plus handoff docs. **Eval-auto candidate**: Overtime as the wake/budget/resume layer around Grok Build (as a `customBackends` entry, if Grok Build speaks ACP; not verified) or a local OpenCode + Ollama backend, versus today's one-shot headless `/orchestrator` run that stops when the session ends.
- **Fit on nimo**: Yes for the CLI and daemon: `npm install --prefix ~/DEVELOP/pfy-mentat/tmp/overtime --ignore-scripts @ukanwat/overtime@0.5.3` plus a Node >= 22.19 tarball under `tmp/overtime/node` if nimo's Node is older. A real agent run needs a backend we can use: not `claude` or `codex` (no keys); Grok Build via ACP or OpenCode pointed at local Ollama are the candidates. Keep `HOME` (and so `~/overtime`) under `tmp/` for any trial, never run `overtime daemon install` (login autostart outside `~/DEVELOP`), and set a workspace that is a throwaway worktree, never Mark's main checkout.
- **Verified on the Grok Bot box** (`/tmp`, temp HOME, Node 22.23.3 from the nodejs.org tarball checked against `SHASUMS256.txt`): with Node 20 the CLI refuses to start. `overtime new smoke-agent` created the folder and auto-started the daemon; `ls`, `settings`, `set budget=1 protect=<dir>` worked and landed in `.overtime/settings.json`; the agent's `state.json` showed no session run; `overtime models` listed Claude models and reported codex "Authentication required" and gemini/opencode not installed; `daemon stop` stopped it. The default backend is `claude` with a $100/day budget, so a trial must set backend and budget before the first `send`. **Finding**: the README says that if anything other than the app changes AGENT.md's settings block, "Overtime puts it back, so no agent can raise its own budget", but a plain file edit raising `dailyBudgetUsd` to 999 while no session was running was logged as "adopted the settings you edited in AGENT.md" and applied. Whether an edit made by the agent during a session is reverted was not tested. Not verified: any session, wakes, watches, helpers, MCP, the TUI.
