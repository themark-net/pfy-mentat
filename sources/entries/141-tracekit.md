### Entry 141: Tracekit: policy-gated, signed, offline-verifiable records of what an agent's tool calls did

- **Summary / Key Claims** (upstream README at 1.4.1; their claims except where marked verified): every tool call goes to a signer before it runs and gets `allow`, `deny` or `ask` from YAML policy packs (`coding`, `server-*`, `browser`, `strict`...). A held call runs only after an approval, and only with the exact arguments approved. Each call and decision is signed (Ed25519) into a hash chain; a run exports to one `.tkb` bundle that `tracekit verify` checks offline against a trust file pinning the log key and witnesses. Witnesses cosign checkpoints, Certificate Transparency style. Integrations: Claude Code hooks (`tracekit init`), Codex/Cursor/Gemini CLI (experimental), the OpenAI Agents SDK, LangChain/LangGraph, MCP (a gateway), OpenTelemetry, LiteLLM and more; `tracekit.instrument()` patches the frameworks it finds. Their numbers: 8/8 tamper attacks caught with a witness, 570/570 harmful calls stopped with 1 false alarm in 738, under 1 ms per call. Their own limits: same-user dev mode protects nothing against an agent that runs as you, rules match text and can be reworded, and actions outside the capture path leave no record.
- **Why it matters here**: pfy-mentat's gate receipts are JSON files the agent that made them could have edited. Tracekit adds the two things we lack: a pre-execution policy on the agent's Bash calls (complementing Sandlock's kernel confinement, Entry 096, which stops the write but keeps no signed record) and a record that the Tester/Reviewer gate can verify did not change after the run. neatroots (Entry 137) checks traces after the fact for loops and leaks; Tracekit decides before the call and proves the record. They stack: Tracekit for the run's evidence, neatroots for rules over it.
- **Fit on nimo**: Yes. A venv under `~/DEVELOP/pfy-mentat/tmp/tracekit/venv` with `pip install tracekit-ai==1.4.1` is 44 MB (cryptography, google-re2 wheel, regex, rfc8785). Pure CPU, Python 3.9+ (integrations 3.10+). The dev signer is a Unix socket; data dir, client home and runtime dir can all be pointed into `tmp/`.
- **Verified on the Grok Bot box** (system Python 3 venv, bubblewrap 0.12.0 with no network, temp HOME; `XDG_DATA_HOME`, `TRACEKIT_CLIENT_HOME`, `TRACEKIT_RUNTIME_DIR` and the signer data in the temp dir): smoke PASS. `tracekit --version` and the module both 1.4.1. Through a same-user dev signer with an in-process test witness (the pieces `tracekit demo --server` uses), the dev policy allowed `ls` and `git status`, denied `sudo rm -rf /` (`TK-D001 TK-D004 TK-F003`) and `curl ... | sh` (`TK-D002 ...`), and held an unparsable command (`TK-SHELL-PARSE`). After approval, replaying it with other arguments was refused and the approved ones accepted. `tracekit verify --json --trust` on the export: exit 0, Integrity VERIFIED, with the swapped-argument attempt signed in as an `approval.binding_mismatch` gap. A copy with the denied call rewritten as allowed and the manifest re-hashed failed at `signatures`; a copy with one record dropped (manifest re-hashed) failed at `run chain`; the real bundle against a trust file pinning another witness failed at `witness quorum`. Temp HOME, `~/.tracekit-client`, `~/.tracekit-signer` and `~/.local/share/tracekit` unchanged.
- **Findings**:
  - **`tracekit demo --server` hard-codes `/tmp`** (`mkdtemp(dir="/tmp")`, for macOS socket-path limits), so under a sandbox with a read-only `/tmp` it exits 1 with EROFS. The smoke drives the same signer pieces in its own temp dir instead.
  - **A refused argument swap is a WARN, not a FAIL**: the bundle still verifies, and the mismatch sits in the `gaps` check. A gate must read `gaps`, not only the exit code.
  - A naive tamper that leaves the manifest alone is caught at `manifest`; re-hash the manifest and it is still caught, at `signatures` or `run chain`. That is the guarantee worth having.
  - `tracekit init` writes Claude Code hooks (`~/.claude/settings.json`) and `tracekit up`/`instrument()` start a dev signer under `~/.local/share/tracekit` and `$XDG_RUNTIME_DIR/tracekit`. On nimo point all of it at `tmp/` or don't use those commands.
  - Dev mode is `isolation: same-user`: an agent running as Mark could read the signing key. Real evidence needs the signer under another user and a witness, which we don't run yet.

- **How this fails / how we recover**:

| Risk | How it fails | Recovery |
|------|----------------|----------|
| Same-user signer | The agent reads the dev key and re-signs an edited log | Treat dev runs as tamper-evident only against accidents; a trial with the signer as a separate user plus a witness comes first |
| Capture gap | A subprocess the hook never sees leaves no record | Route Bash through one gated entry point; compare record counts with the harness log |
| Policy reworded around | A destructive command phrased differently is allowed | Policy is defence in depth next to Sandlock (096), not the boundary |
| Internal API drift | `demo_server` helpers change and the smoke breaks | Pin 1.4.1; switch the smoke to the public SDK when a trial wires it in |
