- **Summary / Key Claims** (homepage, SKILL.md 0.1.7, docs at https://monid.ai/docs, repo README at `96e1569dee3a`): "OpenRouter for agent tools". One API key and one prepaid balance in front of many data vendors: web search (Exa), scraping (Apify, Firecrawl), browser automation (Browserbase), people and company data (Apollo, People Data Labs), SEO (Ahrefs), voice (ElevenLabs), email (AgentMail), social scrapers (Reddit, TikTok, Instagram, YouTube, X, the Chinese platforms), Amazon and other stores, DeFi (DefiLlama, QuickNode), media generation. The tool count differs by page: 1,800+ tools (homepage meta and og description at this read; the page body still says 1,700+ tools across 55+ providers), 1,000+ (llms.txt), 2,000+ across 72+ (repo README). Three verbs: `discover` ranks endpoints for a plain-language need with price, health and p50/p95 latency; `inspect` returns the input schema and live price; `run` executes. Discover and inspect are free; runs are billed per call (e.g. $0.003) or per result plus a base fee, from a prepaid balance with free signup credit, no subscription. Connect through the skill plus CLI, a remote MCP, the REST API (`https://api.monid.ai/v1/*`), OAuth for platforms, or x402 (USDC per run, $0.01 minimum). Contributors add a provider by sending a declarative connector as a pull request.
- **Why it matters here**: Mark only holds Grok and Cursor keys and prefers local models. Monid could be an optional side door for the few paid-data calls we have no key for (people enrichment, SEO data, scraping of sites that block us), paid per call instead of a subscription per vendor. It is not a model router, so it does not touch the local lane or Entry 122 (llm-router).
- **Findings** (read on the Grok Bot box; no account, no key, no run, no spend):
  - **Self-hosting skips Monid's balance but not the vendors' keys.** The open repo is the connector layer and engine. `deno task engine:run '<provider>#<endpoint>'` runs one endpoint locally with that vendor's own key from `<PROVIDER>_CREDENTIALS_<FIELD>` (or `<PROVIDER>_API_KEY`). Every one of the 32 providers in the repo (719 endpoint definitions) declares an auth header, including the ones Monid marks `FREE`. What stays hosted: ranked discover, health data, the wallet, pooled vendor accounts, the MCP server and the providers not yet in the repo (AGENT.md says the older adaptors live in a private `monid-services` repo and are being moved over). Self-hosted Monid is a schema library, not a free side door.
  - **MCP**: `https://mcp.monid.ai/v1`, Streamable HTTP, auth by OAuth (log in to a Monid account in the browser and authorize; the Grok Bot listing says OAuth 2.1). REST and CLI use a bearer key `monid_live_...` made at app.monid.ai. `MONID_API_BASE_URL` points the CLI, skill and MCP at your own proxy instead.
  - **Failed calls**: the docs say provider errors cost nothing. A sync run whose vendor answers 404, 429 or 500 still ends `COMPLETED` with `providerResponse.httpStatus` set, `billedUnits` 0 and `cost.value` 0. The engine bills on the raw envelope before output mapping and bills zero for every non-2xx. `STOPPED` and `TIMED_OUT` runs cost nothing. A run's estimated cost is held while it runs and settled when it finishes. Two caveats: a vendor 2xx with a wrong or empty result is still billed, and the balance API says the balance "may be negative". That billing rule is narrower than the homepage FAQ ("A provider failed. Do I get charged?" "No. We only charge when the request actually delivers results to your agent."), which offers a refund on request for charges made in error.
  - **Data and privacy**: every input (names, emails, domains, search terms, files via the `sfs` store) goes to Monid and then to the vendor under Monid's account, so two third parties see it. Run records keep `input` and `output` (`GET /v1/runs/:id`). The privacy notice and terms (2026-04-23) are generic. They say Monid "will maintain certain data that you transmit" but give no retention period for run payloads, no no-training statement and no DPA. `sfs` files are never auto-deleted. Treat anything sent as shared with Monid and the vendor: no secrets, no repo code, no other people's data without Mark's say.
  - **The skill pushes paid use.** SKILL.md tells the agent to run `monid discover` "proactively" before writing a scraper or saying something is out of reach, to `npm install -g` the CLI, and to pull the latest SKILL.md on each version mismatch. Its own rules do say to prefer the user's tools and to report costs. For us that means a remote file can change agent instructions, and an agent may reach for paid runs on its own. Don't install the skill as is. Use a pinned copy with a rule that every run needs Mark's OK.
  - The tool counts don't match across Monid's own pages, and the open repo holds fewer providers than the hosted catalog. Count what `discover` returns, not the marketing number.
  - Monid is listed in the Grok Bot plugin marketplace (skill plus hosted MCP over OAuth), so Mark can add it there without a CLI install on nimo.
- **Compared with what we use**: web search and page fetch already come free through the Grok and Cursor tooling, local fetch with curl, and the box browser. Camofox (Entry 071) covers anti-bot browsing on our own machine. X data comes through the X connector and bookmarks. The daily intake reads GitHub, arXiv and npm directly. Local models do the reading and summarising. What we lack is paid data with no free source: people and company enrichment, SEO and backlinks, some social scrapers at volume. Only those would be worth a Monid call.
- **Money**: any balance, even the free signup credit or a $5 top-up, is spend under the money priority, so it is Mark's decision. Making the account, entering a card, buying credits and adding the MCP or plugin all need his explicit OK first. If he says yes, set a workspace budget and a per-run cap in the dashboard (runs over the cap come back `BLOCKED`), keep `maxItems` at 5-10, and log `cost.value` for each run.
- **Fit on nimo**: Not needed on nimo. The hosted MCP or the Grok Bot plugin needs no local install. The CLI wants `npm install -g` (outside `~/DEVELOP`), which is a Mark decision. Self-hosted connectors would run under Deno 2 in `tmp/`, but only with vendor keys we don't have.

| Risk | How it fails | Recovery |
|------|----------------|----------|
| Unapproved spend | An agent follows the skill's "discover proactively" rule and runs paid endpoints | No key or MCP on any bot without Mark's OK; if he approves, workspace budget plus run cap, and every run asked for first |
