### Entry 085: Kolibri-1 — Aleph Alpha German/English reasoning MoE (open weights)

- **URL**: https://x.com/Aleph__Alpha/status/2106306843052052616
- **Date**: 2026-10-03 (model release); cataloged 2026-10-04 (operator request: "Add to pfy-mentat. Pull it and test.")
- **Poster**: Aleph Alpha (@Aleph__Alpha)
- **Summary / Key Claims** (from the model card, https://huggingface.co/Aleph-Alpha/Kolibri-1): Mixture-of-Experts reasoning model, 78B total / 3.46B active parameters, German + English. Context up to 1,048,576 tokens; 262,144 is native and is the recommended maximum. Has tool calling and a reasoning mode: `reasoning_effort` is `none` / `low` / `medium` / `high` through the chat template (`enable_thinking=false` also disables thinking). Apache-2.0 weights. The published checkpoint is FP8 (`float8_e4m3fn`, 128x128 block scales, about 78 GB); `Aleph-Alpha/Kolibri-1-BF16` also exists. Minimum hardware per the card: 2x A100 80 GB, 2x H100 SXM5, 1x H200, 1x B200 or 1x B300. Recommended sampling: temperature 1.0, top_p 0.97, top_k 128 (`generation_config.json`). Card says pre-training used 20T tokens (about 62.5% English, 23.9% German, 13.6% code).
- **Architecture (config.json, verified 2026-10-04)**: `Kolibri1ForCausalLM`, `model_type: kolibri1`. 50 layers, hidden 2560, 48 attention heads / 4 KV heads, head_dim 128. 384 experts, 6 per token, plus a shared expert (moe and shared intermediate size 512). Sliding window of 513 with a full-attention layer every 5th layer. Vocab 128,000 with a German-tailored tokenizer. ChatML-style template with `<think>` and Hermes-style `<tool_call>` JSON.
- **Serving (official)**: Needs the Kolibri vLLM plugin, `pip install 'aleph-alpha-inference>=1'`, or the container `ghcr.io/aleph-alpha/aleph-alpha-inference`. Serve with `vllm serve Aleph-Alpha/Kolibri-1 --kv-cache-dtype fp8 --reasoning-parser kolibri1 --tool-call-parser kolibri1 --enable-auto-tool-choice`. The API is OpenAI-compatible. Tech report: https://aleph-alpha.com/downloads/tech-report.pdf
- **Runtime support (checked 2026-10-04)**: Stock llama.cpp and Ollama do **not** support `kolibri1` (open request ggml-org/llama.cpp#29922). Community GGUFs need a source patch, for example `Eliasfpv28/Kolibri-1-Q3_K_S-GGUF` (33.87 GB, patch on llama.cpp `edd6e2b`) and `Hob-forge/Kolibri-1-GGUF` (Q4_K_M 47.45 GB, patch on `836d571`). MLX quants exist (Apple only). NVFP4 and W4A16 quants are vLLM-only. Kolibri is not listed on OpenRouter. It has no HF inference-provider mapping.

- **Run status on our hardware (nimo, 2026-10-04)**: No NVIDIA GPU, so the official FP8/vLLM path cannot run (it needs at least 160 GB of NVIDIA-class VRAM). nimo is an AMD Strix Halo APU (Radeon 8060S iGPU, 64 GiB VRAM carve-out, 61 GiB system RAM). The most real local path is the community Q3_K_S GGUF plus the patched llama.cpp. That build compiles on nimo (CPU backend, `edd6e2b` + patch). The GGUF was still downloading when this entry landed (the link is about 8-10 MB/s). Smoke: `make smoke-kolibri1` (examples/kolibri1-llamacpp). It FAILs loudly until a backend answers. Vulkan (to use the 64 GiB iGPU) needs Vulkan headers and `glslc`, which nimo does not have; see the handoff.
