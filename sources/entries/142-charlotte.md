### Entry 142: Charlotte: a browser MCP server that returns structured, token-bounded pages instead of accessibility dumps

- **URL**: https://github.com/TickTockBent/charlotte (MIT, TypeScript; 183 stars at this read; npm `@ticktockbent/charlotte@0.8.0`, 2026-08-09, published from commit `208f6727467993d857ff1e527a470b6877b3ff97`; tag `v0.8.0` at `932e95aa6095aaa1089d9b71ae49750690b9765e`; `main` is 111 commits past the tag, unreleased). - **Summary / Key Claims** (upstream README at 0.8.0; their claims except where marked verified): puppeteer drives a headless Chromium and each page comes back as landmarks, headings, typed interactive elements with bounds, forms and a content summary, at three levels: `minimal` (orientation, ~50-200 tokens, counts per region and no element list), `summary` (the element list, ~500-5000) and `full` (plus visible text). Element ids (`btn-a3f1c2`) are hashes of type, role, name and DOM path, stable across unrelated DOM changes. Tool profiles bound the definition overhead: `core` 7 tools, `browse` 23 (default), `full` 43; `charlotte_tools` loads groups on demand. Limits (`maxResponseBytes` and others) degrade a huge page to a summary. stdio by default; an HTTP mode ("Charlotte Remote") adds an SSRF guard proxy. Chromium's sandbox is on by default since 0.7.0.
- **Why it matters here**: browsing on nimo means a local model with a small context. A raw accessibility dump of one page can fill it; Charlotte's minimal level is a few hundred bytes, and the agent asks for detail only where it needs it. With the `core` profile only 7 tool definitions ride along on every call. That makes browser tasks a plausible job for `qwen3.6:35b` under Hermes (Entry 134) rather than Grok-only.
- **Fit on nimo**: Yes, with a browser. `PUPPETEER_SKIP_DOWNLOAD=1 npm install --prefix ~/DEVELOP/pfy-mentat/tmp/charlotte @ticktockbent/charlotte@0.8.0` is 85 MB (192 packages) and needs Node 20+. Chrome or Chromium is separate: an installed `chromium`/`google-chrome`, or Chrome for Testing 148.0.7778.97 (puppeteer 24.43.1's pin) fetched with `npx @puppeteer/browsers install chrome@148.0.7778.97 --path ~/DEVELOP/pfy-mentat/tmp/charlotte/browsers` (a few hundred MB) and linked as `tmp/charlotte/chrome/chrome`. CPU rendering; nothing needs the GPU.
- **Verified on the Grok Bot box** (Node 24.14.1, the box's Google Chrome 155 via `PUPPETEER_EXECUTABLE_PATH`, bubblewrap 0.12.0 with no network, temp HOME, `TMPDIR` and `XDG_*` in the temp dir, `--profile core --no-sandbox`): smoke PASS. `serverInfo` 0.8.0, exactly the 7 core tools. On a `file://` fixture form, `charlotte_navigate` returned the minimal level (724 bytes: title, 3 landmarks, 2 headings, 3 interactive elements counted, no ids, no body text); `charlotte_observe` (1,157 bytes) listed the "Order number" input and "Look up" button; `charlotte_find "Look up"` returned the same button id; `charlotte_type` then `charlotte_click` ran the page's own submit handler, and `observe` at `full` (1,305 bytes) showed "Result for 4242" and the body marker. Ids were identical across observes. A click on an unknown id returned `ELEMENT_NOT_FOUND` with a "did you mean" suggestion and the server kept answering. Fixture, temp HOME and `~/.cache/puppeteer` unchanged; no puppeteer profile left in `TMPDIR`.
- **Findings**:
  - **stdio mode reads local files**: `file://` URLs load, and the SSRF guard only runs in HTTP mode, so an agent with Charlotte can read anything the account can. On nimo run it inside bwrap or Sandlock (096) with only the worktree visible.
  - **It does not exit on stdin EOF** (0.8.0); it needs SIGTERM. A SIGTERM without closing stdin first left `puppeteer_dev_chrome_profile-*` in `TMPDIR` in 3 of 3 tries; EOF, then SIGTERM a couple of seconds later, cleaned it up in 5 of 5.
  - Chrome writes to `~/.config/google-chrome` (crash reports), `~/.cache/fontconfig` and `~/.local/share` unless `XDG_CONFIG_HOME`, `XDG_CACHE_HOME` and `XDG_DATA_HOME` point elsewhere. Without `PUPPETEER_SKIP_DOWNLOAD=1` the install downloads Chrome into `~/.cache/puppeteer`.
  - Screenshots go to `$TMPDIR/charlotte-screenshots` by default.
  - The smoke turns Chrome's sandbox off (`--no-sandbox`) because bwrap is the sandbox there and only a local page loads. On nimo with real sites, keep Chrome's sandbox on.

- **How this fails / how we recover**:

| Risk | How it fails | Recovery |
|------|----------------|----------|
| Local file read | A prompt-injected page or task makes the agent open `file:///home/...` | Run Charlotte under bwrap or Sandlock with only the worktree; never with `~` visible |
| Orphaned Chrome or profile | The server is killed and Chromium or its temp profile stays | Close stdin, then SIGTERM; run under a process group or `--die-with-parent` |
| Version gap | `main` is 111 commits past the `v0.8.0` tag (107 past the published commit); behaviour differs from the README | Pin the npm version; re-read the changelog before an upgrade |
| Chrome mismatch | A system Chrome far from puppeteer's 148 breaks CDP calls | Use Chrome for Testing at puppeteer's pin under `tmp/` |
