### Entry 103: BugPatrol — autonomous QA patrol (explore, judge, fix, retest) with a custom OpenAI-compatible endpoint route

- **URL**: https://github.com/agent-labs-dev/bugpatrol (Apache-2.0, TypeScript, about 107 stars at this read, npm `bugpatrol` 0.3.0, Node 22+)
- **Date**: 2026-10-09 (daily X intake)
- **Source / Poster**: @FurqanR, https://x.com/FurqanR/status/2108258307693760921
- **Summary / Key Claims** (upstream README and docs): "A QA team made of agents." `npx bugpatrol` runs a patrol loop: an explorer agent uses the app (web via Playwright, Electron via CDP, iOS/Android via Maestro, Linux desktop via Cua + Xvfb, HTTP APIs and CLIs), a judge agent decides which reports are real bugs and writes issues, a fixer writes a fix in its own git worktree, and explorer + judge retest the fix in the running app before anything is published. The fixer and GitHub publishing are off by default. Each agent can use a local agent CLI (Claude Code, Codex, Kimi CLI, pi, or any CLI through `runtime: cli`) or a model route (`via: openrouter | vercel | openai | anthropic | custom`); `custom` takes a `model` and an `endpoint` with `BUGPATROL_MODEL_API_KEY`. Also ships `bugpatrol review <pr>` (claim checks on a PR), a deterministic no-model web gate (`bugpatrol run --no-models`), and a local dashboard on 127.0.0.1:4311. Everything lives in one `.bugpatrol/` folder; `runs/` is git-ignored.
- **Fit on nimo**: Node CLI, no GPU of its own. The only allowed model route here is `via: custom` pointed at nimo's local Ollama OpenAI-compatible endpoint (`http://127.0.0.1:11434/v1/chat/completions`), since there are no paid provider keys. Every request carries tool definitions, so the local model must do tool calls (`qwen3.6:35b` is the current decision-bench pick); the web/Electron explorer also wants vision, which none of our benched local models has been tested for. CLI and HTTP API targets need no browser. A web target needs Playwright Chromium, whose default cache is `~/.cache/ms-playwright` (outside `~/DEVELOP`, so Mark approval first, or set `PLAYWRIGHT_BROWSERS_PATH` under `~/DEVELOP/pfy-mentat/tmp`). The patrol changes the checkout it runs in, so it must never run in Mark's main checkout; a throwaway clone or worktree under `tmp/` only.
- **Verified on the Grok Bot box** (`/tmp`, Node 22.23.3 from the official tarball, `npm install --prefix /tmp/... bugpatrol@0.3.0`): `bugpatrol --help` and `--version` (0.3.0) run. On a throwaway CLI-platform git repo with explorer and judge on `via: custom` pointed at a stdlib fake OpenAI-compatible server on 127.0.0.1, `bugpatrol explore --steps 2` exited 0, sent all 3 model calls to that local `/v1/chat/completions` with the configured model name and dummy key (two calls offered 10 tools), and raised 0 candidates from a model that never called a tool. The same config with no `endpoint` was refused (exit 2, "The explorer uses a custom model, but it has no endpoint.") with no request sent. Not verified: a real patrol cycle, judge quality, the fixer, a web target, or any real local model (no Ollama on the box). The smoke below PASSed there.
- **Why it matters here**: Candidate for an eval-auto trial against our current Tester-bot GUI checks and the CUA lane on pfy-mentat GUI PRs. Its explore → judge → retest loop with a judge that has to confirm a fix in the running app is close to what we ask Tester to do by hand, and `bugpatrol review <pr> --dry-run` could give a second opinion on a PR without posting anything. The local endpoint route means it can run on nimo with no new key.

- **How this fails / how we recover**:

| Risk | How it fails | Recovery |
|------|----------------|----------|
| Local model can't drive the tools | Explorer replies without tool calls ("Model replied without a tool call") and maps nothing | Trial with the decision-bench pick first; record steps-with-tool-calls in the receipt; fall back to `runtime: cli` with a local CLI agent |
| No vision | Web/Electron explorer can't read screenshots on a text-only model | Start with CLI and HTTP API targets; only try web once a local vision model is benched |
| Paid route by accident | A provider key in the env makes `via: auto`-style resolution pick a paid route | Config pins `via: custom`; smoke strips provider keys and FAILs on any call that isn't the local endpoint |
| Checkout churn | Patrol pulls `origin/main` and edits the checkout it runs in | Only in a throwaway clone/worktree under `~/DEVELOP/pfy-mentat/tmp` |
| Early-version churn | 0.x config keys or output change | Smoke FAILs with a "shape changed?" reason; pin `bugpatrol@0.3.0` in the prefix |
