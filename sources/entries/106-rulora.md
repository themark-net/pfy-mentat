### Entry 106: Rulora — pluggable controls for agents: validated outputs, bounded loops, frozen candidate selection (no model needed)

- **URL**: https://github.com/Buffalo2024/Rulora (Apache-2.0, JavaScript, 123 stars at this read, npm `@rulora/core` 0.1.0-alpha.4 on the `alpha` tag, Node 20+, no runtime dependencies; checked commit `7b09de37dddc`)
- **Date**: 2026-10-10 (daily X intake)
- **Source / Poster**: @DanKornas, https://x.com/DanKornas/status/2108897575323533581
- **Summary / Key Claims** (upstream `README_EN.md`, `docs/guarantees.md`): "Pluggable controls for reliable AI agents: validated outputs, bounded loops and frozen collective decisions." Models understand and create; programs control, validate and deliver. Core exports `OutputBoundary` (recover → adapt → ordered validators; anything not `true` is rejected and the error names the stage, e.g. `core` or `audit`), `LoopControl` (per-kind counters for `network_reconnect`, `constraint_revision`, `business_broadcast`; stops at `human_handoff` after N no-progress attempts or `exhausted` at the attempt cap, then refuses further records with `LOOP_CLOSED`), `CollectiveControl` (recursively frozen candidate snapshots; a reviewer may only select an existing id, otherwise `UNKNOWN_CANDIDATE`), plus `OrchestrationMachine`, `MemoryRepository` (in-memory only) and `HybridPipeline`. The quickstart examples and the collective-decision demo need no API key and make no model call. The guarantees doc is explicit that these are counters and validators: no scheduling, no global cost cap, no cancelling in-flight requests, no proof that a chosen answer is correct, and not a sandbox for untrusted JS. The main README is Chinese; `README_EN.md` is the English copy.
- **Fit on nimo**: Pure Node library, no GPU and no model of its own, so it fits trivially on nimo (AMD Strix Halo, 128 GB total, ~107 GB visible to Linux, no NVIDIA). Install as an npm `--prefix` under `~/DEVELOP/pfy-mentat/tmp/rulora`; Node 20+ is enough. Any model it guards would be the host's job: on nimo that means local Ollama (`qwen3.6:35b` is the decision-bench pick), since there are no paid API keys beyond the Grok subscription and Cursor plan. pfy-mentat is Python, so using it means a Node subprocess or porting the contracts; it cannot be imported by `./pfy decision` directly.
- **Verified on the Grok Bot box** (`/tmp`, Node 22.23.3 from the official tarball and the box's Node 20.19.2): `npm install --prefix /tmp/... --ignore-scripts @rulora/core@0.1.0-alpha.4` added 1 package. In a clone of the repo, `npm run example:output`, `example:loop`, `example:candidates` and `node examples/collective-decision/examples/controlled-collective.js` all ran offline and printed their JSON (the collective demo ended with seat-c at `human_handoff`). `npm test` was 24/25 without dev dependencies (the Ajv JSON-schema test needs `ajv`), 26/26 after `npm ci --ignore-scripts`. The smoke below PASSed on both Node versions and also with networking removed (`unshare -rn`). A stub copy whose loop never hands off made it exit 1. Not verified: any real model behind the controls, `OrchestrationMachine`, `HybridPipeline`, or the collective-decision console.
- **Why it matters here**: Small, deterministic shapes for three things our loop and decision work already cares about: reject a model output before it is used, stop a loop after N no-progress turns with an explicit handoff state (Entry 068's "no progress" and "human interrupt" exits), and let a reviewer pick only among frozen candidates (close to `./pfy decision` returning a typed Choice over options rebuilt from live state). Mostly a pattern reference: the loop and collective controls are a few dozen lines each. Not an eval-auto candidate on its own; if anything, port the `LOOP_CLOSED` / `UNKNOWN_CANDIDATE` contracts into pfy tests.
