### Entry 113: Festival — filesystem-and-git plan/gate/next loop for long-running agent work (works with Grok Build)

- **URL**: https://github.com/Obedience-Corp/festival (Apache-2.0, Go binaries, 64 stars at this read; release v0.3.20 published 2026-10-12, `fest` v0.9.5 and `camp` v0.14.0; npm `@obedience-corp/festival` 0.3.20 downloads the same binaries in a postinstall)
- **Date**: 2026-10-12 (daily X intake)
- **Source / Poster**: @DanKornas, https://x.com/DanKornas/status/2109554403363463505
- **Summary / Key Claims** (upstream README, `fest --help`, `fest create festival --help`): "a vibe engineering framework" that "uses the filesystem and Git." A *camp* is a workspace (skills, planning docs, scripts, linked project repos); a *festival* is one ambitious goal inside it, laid out as phases, sequences and tasks with quality gates (testing, review, iterate, commit). "You describe a goal in a sentence. Your agent plans that goal inside the workflows you set up, and `fest next` shows it the next step. The plan, the checks, and the commits stay in files and Git when the session ends." Named hosts: "Claude Code, Codex, Grok Build, Cursor, OpenCode, or another agent that can read files and run commands." `fest create festival --agent` is a strict mode that rolls back on blocking errors and emits JSON.
- **Why it matters here**: Same problem Mark keeps hitting with Build (work stops or drifts when a session ends) attacked from the plan side rather than the scheduler side: the next step, its gates and the evidence live in git, so any harness can resume. Comparison point for our orchestrator lane, loop-exits-first skill, Tester/Reviewer gates and handoff docs. It overlaps Brigade (Entry 110) on the ledger idea but is plan-and-gate first. No eval-auto trial yet: we already have a working loop, and Festival would be a second methodology; worth one small side-by-side on a real pfy-mentat backlog item.
- **Fit on nimo**: Yes. Static Linux x86_64 binaries from the release tarball unpacked under `~/DEVELOP/pfy-mentat/tmp/festival/`. No model, no account. `camp create` writes under `~/campaigns` and `fest` config under `~/.obey`, so a trial runs with `HOME` under `tmp/`. Don't use `brew`, `npm install -g`, or `festival update`, and don't add its `shell-init` lines to Mark's shell config.
