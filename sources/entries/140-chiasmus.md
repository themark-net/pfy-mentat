- **Summary / Key Claims** (upstream README at 0.1.40; their claims except where marked verified): a stdio MCP server (plus an optional loopback HTTP daemon, `chiasmus-http`) with Z3 (`z3-solver` WASM) and SWI-Prolog (`prolog-wasm-full`, with `clpfd`) solvers and tree-sitter call graphs for TypeScript, JavaScript, Python, Go, Rust, Clojure and three Lisps. Tools: `chiasmus_verify` (raw SMT-LIB or Prolog; Z3 UNSAT returns an unsat core, Prolog can return a derivation trace, Mermaid flowcharts parse to facts), `chiasmus_graph` (callers, callees, reachability, dead code, cycles, impact, layer violations, diff against a snapshot, raw Prolog facts), `chiasmus_map` (a codebase outline before bulk reads), `chiasmus_skills`/`chiasmus_formalize`/`chiasmus_craft` (a template library of 8 starter checks: policy contradiction, dependency resolution, validation boundaries, workflow reachability...), `chiasmus_review` (a phased review recipe), `chiasmus_lint`. The calling LLM fills template slots and calls `chiasmus_verify`, so no API key is needed; only the optional `chiasmus_solve` (autonomous slot filling) and `chiasmus_search` (embeddings) want a provider, and both can point at local endpoints (`CHIASMUS_API_URL`, or node-llama-cpp embeddings).
- **Why it matters here**: Tester and Reviewer currently argue about rules, dependency pins and "can this input reach that sink" from reading code. A solver answers those with a model or an unsat core instead of a guess, and `chiasmus_graph impact`/`dead-code` gives Reviewer a checkable blast radius for a diff. The decision layer could also ask `chiasmus_verify` whether a set of gate rules (catalog HOLD, Build-only, LIVE_HARD_OFF) can ever both allow and deny the same action. It is a tool for the model we already run, not another model.
- **Fit on nimo**: Yes. `npm install --prefix ~/DEVELOP/pfy-mentat/tmp/chiasmus --ignore-scripts --omit=optional chiasmus@0.1.40` is 180 MB (128 packages; `npm install --dry-run` with the same flags on nimo, 2026-10-21; 241 without `--omit=optional`) and needs Node 22+. Z3 and Prolog are WASM; tree-sitter, better-sqlite3 and most grammars ship linux-x64 prebuilds, so no compiler is needed. CPU only, no GPU. A Node 22+ tarball unpacked under `tmp/chiasmus/node` if nimo's `node` is older.
- **Verified on the Grok Bot box** (Node 24.14.1 from the official tarball, bubblewrap 0.12.0 with no network, temp HOME, `CHIASMUS_HOME` and `CHIASMUS_CACHE_DIR` in the temp dir, no provider key): smoke PASS. `serverInfo` 0.1.40 with 9 tools. Z3: `x>10 ∧ x<5` unsat with core `[gt10, lt5]`; `10<x<15` sat with `x = 11`. Prolog proved `reach(a,c)` over two edges and found no `reach(c,a)`. On a 2-file Python fixture `chiasmus_graph` listed `unused_helper` as dead, said `handle` reaches `connect` and `unused_helper` doesn't, and gave `impact(connect) = [query, handle]`. `chiasmus_lint` caught an unclosed parenthesis; `chiasmus_skills` returned `policy-contradiction`, `policy-reachability` and `boundary-condition` for an access-control question. The skill DB went to the temp `CHIASMUS_HOME/chiasmus.db` only; fixtures, temp HOME, `~/.chiasmus` and `~/.cache/chiasmus` unchanged. Node 20 gives exit 2.
- **Findings**:
  - **It writes `~/.chiasmus/chiasmus.db` on start-up** (the skill library) unless `CHIASMUS_HOME` is set, and `cache=true` writes `~/.cache/chiasmus` unless `CHIASMUS_CACHE_DIR` is set. Set both for every run on nimo.
  - **A plain `npm install` fails without `make`**: `@yogthos/tree-sitter-clojure` builds from source with node-gyp. `--ignore-scripts` skips it (Clojure analysis is then unavailable; Python, TS/JS, Go and Rust use prebuilds and worked). `--omit=optional` leaves out node-llama-cpp, which would otherwise fetch binaries and, on first use, a GGUF from Hugging Face.
  - `dead-code` reports every function nobody calls, entry points included (`handle` showed up next to `unused_helper`). Give it entry points or filter them before treating the list as a finding.
  - `chiasmus_skills` returns whole templates (skeleton, slots, normalizations), several KB each: cheap for Grok, but watch it on a small-context local model.
  - The HTTP daemon has no auth; it checks `Host`/`Origin` for loopback only. Keep it on stdio.

- **How this fails / how we recover**:

| Risk | How it fails | Recovery |
|------|----------------|----------|
| Writes the real HOME | `~/.chiasmus/chiasmus.db` or `~/.cache/chiasmus` appear on nimo | Always set `CHIASMUS_HOME` and `CHIASMUS_CACHE_DIR` under `tmp/`; the smoke watches both |
| Wrong formalization | The model fills a template that doesn't say what the rule says, and the solver proves the wrong thing | Keep a known-sat and a known-unsat case per template we rely on; read the unsat core, not only the status |
| Solver blow-up | A big input exhausts Z3's 2 GiB WASM heap or the stack | It returns an error and replaces the child; cap inputs and set `CHIASMUS_SOLVER_JOB_TIMEOUT_MS` |
| Native module drift | A new version drops a prebuild and needs `make` | Pin the version; `--ignore-scripts` and check the language you need still parses |
