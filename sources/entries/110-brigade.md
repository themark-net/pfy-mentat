- **Summary / Key Claims** (upstream README, `QUICKSTART.md`, `docs/first-10-minutes.md`, `brigade --help`, the 0.27.0 wheel source): "Brigade keeps coding-agent work trackable across tools, repos, and sessions: tasks, receipts, shared memory, and synced tools." The work ledger is "machine-local JSON" (`.brigade/work/tasks.json`) with a ready set and atomic claims ("two agents cannot take the same item"; CAS guards `--if-actor`/`--if-status`). `brigade work verify run` writes a receipt with the command, the real exit code, the Git state and sha256 digests of the receipt and its logs; `brigade receipts verify` re-checks those digests (plus optional SSH-signed in-toto attestations). Handoffs are linted notes routed into memory by a "memory owner"; harness projection of MCP servers, tools and skills into 19 harnesses (Claude Code, Codex, Cursor, Grok CLI, OpenClaw, ...) is dry-run first. "Nothing runs until a command or an operator-owned scheduler starts it"; no daemon, optional foreground `serve` commands, an optional fleet hub over Tailscale, cloud-work trackers, and "an approved Grok Bot scout feed" that enqueues labeled GitHub issues only after `--apply`. "It does not push to GitHub, publish packages, or send chat messages unless the operator uses an explicit send action."
- **Network and telemetry** (read in the 0.27.0 wheel): Brigade's own "telemetry" (`daily_cmd/telemetry_ops.py`) is local event files under the target, not an upload. The one automatic network call found is a passive update check: a detached child runs `brigade update --notify-refresh` at most once a day against `https://check.brigade.tools/v1/version`, a request with no parameters or install id (the User-Agent carries version + OS), cached in `~/.cache/brigade/update-notify.json`. It is skipped when `BRIGADE_NO_UPDATE_CHECK` or `CI` is set. On the box, a run without that variable created the cache file in the temp HOME (cached `latest` was 0.27.0). Other modules can make network calls when invoked (fleet client, cloud trackers, `brigade setup` / `brigade update` downloads, research web sources); none ran here. This is a read of the code paths we exercised, not a full audit.
- **Fit on nimo**: Pure Python, no GPU, no model needed for the ledger and receipts. A venv under `~/DEVELOP/pfy-mentat/tmp/brigade/.venv` fits the layout lock; `pipx`/`uv tool install` put it in the real HOME, so don't use them. `brigade setup` installs pinned native components (graphtrail, miseledger, sessionfind, agent-notify; each a release binary) and `brigade init` without `--no-wire` writes skills into harness dirs; neither is needed for a first look. Work state lives in the target repo's `.brigade/` (and `init` creates or edits `.gitignore`), so try it in a throwaway clone, never Mark's main checkout. Set `BRIGADE_NO_UPDATE_CHECK=1`.
- **Verified on the Grok Bot box** (`/tmp`, temp HOME, venv with `brigade-cli==0.27.0`; wheel sha256 `ac63094d379459338adde3be6dc49d54d928d5a06663342dec71eee975fed8c1`): in a throwaway git repo, `brigade init --target . --depth repo --harnesses none --no-wire` wrote `.brigade/` and `.gitignore`; `work task add` added a pending task, `work ready --json` listed it, `work claim --next --actor smoke-a` took it (`in_progress`) and a second actor got `no_ready` (exit 1); `work verify run` recorded exit 0 at HEAD with log digests and a failing command's real exit code 3 (status `failed`, CLI exit 3); `receipts verify --json` reported 6/6 OK, and after one appended byte in a log it reported 1 `MISMATCH` and exited 1. The whole flow also ran under bubblewrap with a read-only root, only the temp HOME and repo writable, and no network, so it wrote nothing outside those two (and with `BRIGADE_NO_UPDATE_CHECK=1` the temp HOME stayed empty). The smoke below PASSed in that mode and in the fallback mode without bwrap, and also under `unshare -rn`. Not verified: memory handoffs and ingest, `operator quickstart`, harness projection, skills scoring, fleet hub, cloud trackers, `brigade setup` components, the 0.28 beta.
- **Why it matters here**: Brigade covers, in one CLI, three things we do by hand: the orchestrator-in-worktree lane (Build drop-ins plus GitHub issues as the task list), Tester/Reviewer sha pinning ("checks ran at this sha"), and repo handoff docs plus AGENTS.md as memory. Its receipt carries what our sha pin carries (head, dirty files, tree fingerprint, exit code) plus log digests that `receipts verify` can re-check later, and `work claim` is the claim safety our parallel Build runs lack. It is also large (dozens of subcommands, native components, extras) and wants to own the repo's `.brigade/`, memory routing and harness wiring, which overlaps pfy-mentat's own tooling. Comparison candidate, not first in line: if we try it, use only `work task/claim/verify` and `receipts verify` in a throwaway clone next to our lane, and see whether its receipts replace the hand-written "checks ran at sha X" lines in Tester/Reviewer comments.
