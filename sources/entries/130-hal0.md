### Entry 130: hal0 — self-hosted inference appliance built first for AMD Strix Halo (catalog only)

- **URL**: https://github.com/Hal0ai/hal0 (Apache-2.0, Python; 82 stars at this read; release `v1.4.0`, 2026-10-16; checked at commit `60bcf6f77dc8`)
- **Date**: 2026-10-17 (daily X intake)
- **Source / Poster**: @DanKornas, https://x.com/DanKornas/status/2111309739741135193
- **Summary / Key Claims** (upstream README at v1.4.0): turns a Linux box into one OpenAI-compatible API on `:8080/v1` for chat, embeddings, rerank, speech-to-text, TTS and image generation. Each capability is a systemd-managed podman "slot" running llama.cpp (or Kokoro, Qwen3-TTS, ComfyUI) with automatic backend choice (ROCm, Vulkan, CPU, the XDNA NPU via FastFlowLM, experimental CUDA). First-class target is the **Ryzen AI Max+ 395 / Radeon 8060S / 128 GB**, the same platform as nimo. Ships a dashboard, MCP control surface, `hal0 doctor` and a benchmarking subsystem (`hal0 bench plan|run|results|eval`) with a public leaderboard.
- **Why it matters here**: it is the closest thing to a packaged version of what we hand-built on nimo (Ollama plus llama-server ROCm/Vulkan, Entries 089-094). Its published numbers are from our exact hardware, but on **ROCm 7.2.4**: e.g. `qwen3.6-35b-a3b` at 84.4 tok/s decode and 873 tok/s prefill (f16), and an NPU lane (gemma3:1b at ~38.6 tok/s in ~2 GB) that we haven't touched. Our runtime matrix (Entry 094, ROCm 7.1) had llama.cpp ROCm at 57.2 tok/s decode vs Ollama at 96.4 for `qwen3.6:35b`, so their numbers are a reference for whether a ROCm 7.2 userspace or their runner images would lift the llama.cpp lane. Their claims; not reproduced here.
- **Fit on nimo**: **Not without Mark.** The installer is `curl | sudo bash`, needs systemd, Python 3.12-3.14 and podman (auto-installed), and writes `/etc/hal0`, `/var/lib/hal0` and system units: all outside `~/DEVELOP`. It also wants `:8080`, which clashes with llama-server habits on nimo, and it would compete with Ollama for the same GTT memory.
- **Not verified anywhere**. No smoke: the only honest happy path is a full system install. If Mark ever approves one, a follow-up smoke can read `GET /v1/models` and `hal0 doctor` on the running box.
- **Findings**: **auth is off by default** (trusted-LAN posture) and the optional OpenWebUI companion is a second listener on `:3001` that hal0's auth doesn't cover. Any trial binds loopback or turns `hal0 auth require on` first. The NPU path installs a FastFlowLM `.deb` on the host.

- **How this fails / how we recover**:

| Risk | How it fails | Recovery |
|------|----------------|----------|
| System install sprawl | `/etc/hal0`, units and podman land on nimo | Don't install without Mark; `hal0 uninstall` exists but keep it off the box |
| LAN-open API | Anyone on the LAN can drive models | Loopback bind or `hal0 auth require on` before first start |
| Port and memory clash | `:8080` taken; GTT contention with Ollama | Use `HAL0_PORT`; stop Ollama models during any trial |
| Leaderboard optimism | Their numbers don't match nimo | Re-measure with our own 48-case harness before acting on them |
