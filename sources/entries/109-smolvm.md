- **Summary / Key Claims** (upstream README, release `README.txt`, `smolvm --help`, `docs/branching.md`, `docs/branch-and-checkpoint/`): "Branchable microVMs for AI agents." Each workload runs in a hardware-virtualized VM with its own guest kernel: KVM on Linux, Hypervisor.framework on macOS, WHP on Windows; libkrun is the VMM and libkrunfw supplies the guest kernel. Any OCI image boots as a microVM "with no Docker daemon"; no daemon for the SDKs either (Node, Python, Rust). Claims boot "in under a second" (table: <200 ms), elastic memory via virtio balloon (defaults 4 vCPUs, 8 GiB). `machine run` is ephemeral; `machine create/start/exec/stop/delete` are persistent. Branching: `machine start --branchable`, `machine branch --from` (live copy-on-write child), `machine checkpoint --name X -o file` (RAM, CPU state and disks), restore with `machine create --from <checkpoint>` (there is no `machine restore`), rewind with `--at '~N'`, pause/resume. Networking is off by default; `--allow-host`/`--allow-host-pattern` egress allow lists; `--credential` substitution so a workload can use a secret it never reads. Also `.smolmachine` packs, a Kubernetes RuntimeClass shim, GPU via virtio-gpu/Venus. Hosted "smol cloud" exists but nothing local needs an account.
- **Fit on nimo**: x86_64 Linux tarball (~46 MB; wrapper script `smolvm` + `smolvm-bin`, bundled `lib/libkrun.so` and `libkrunfw.so`, `agent-rootfs/`) that runs from any directory, so it can live under `~/DEVELOP/pfy-mentat/tmp/smolvm/`. Needs `/dev/kvm` read/write for Mark's user (usually the `kvm` group); if nimo's user is not in it, that is a system change needing Mark's approval. Not checked on nimo in this slice. State goes to `~/.cache/smolvm` and `~/.local/share/smolvm` (run with `HOME` under `tmp/`), and the first run unpacks sparse `overlay-template.ext4` (10 GiB apparent) and `storage-template.ext4` (20 GiB apparent) next to the binary; on the box the whole unpacked dir was 122 MB on disk. Each VM defaults to 8 GiB elastic RAM, which is small next to nimo's ~107 GB but matters during a local-model benchmark. **The `curl -sSL https://smolmachines.com/install.sh | bash` installer must not be used on nimo** (it installs outside `~/DEVELOP`); stage the release tarball by hand after checking its sha256.

Not verified: boot time, any guest command, host isolation, checkpoint/rewind, branching, egress allow lists, credential substitution, behaviour on AMD Strix Halo.
- **Why it matters here**: Our unattended Grok Build runs today are isolated only by a git worktree under `~/DEVELOP/pfy-mentat/tmp` with no VM: the agent shares the host kernel, the real HOME, the network and every file Mark's user can write. smolvm would put the run in its own kernel with no host files unless mounted, egress limited to named hosts, and a checkpoint to rewind a run that went wrong. **Possible eval-auto candidate** against the worktree-only lane, once `/dev/kvm` access on nimo is settled: run one small pfy-mentat Build task inside a smolvm machine (repo copy mounted, `--allow-host` for GitHub and the model endpoint only, credentials via `--credential`) and compare setup cost, run time, whether Build works at all inside the guest, and what a checkpoint/rewind buys over `git worktree remove`. The open question is how Build's login (`~/.grok/auth.json`) crosses the boundary without copying the token into the guest.

- **Image digest**: The ref is digest-pinned. Default `SMOLVM_IMAGE_PIN` is the alpine 3.22 multi-arch index (`alpine:3.22@sha256:5291449c3df73caf6ed85e649dec1b9e818b39a5d8c871e97afc13e9cd5e8fa8`, resolved 2026-10-17 from registry-1.docker.io). `$SMOLVM_IMAGE` overrides it only when the ref ends in `@sha256:` plus 64 hex digits (stored lowercase); anything else exits 2 before the KVM check.
