# Hermes bake-off (Entry 134)

Stdlib harness that compares two tool-calling arms on the same tasks, the same model, and the same MCP server. Not a Feature GO. No gateway. `./pfy bot` can opt into Hermes with `PFY_BOT_INTERFACE=hermes`. The default stays opencode (`docs/plans/hermes-bot-interface.md`).

## Arms

Both arms use `qwen3.6:35b` on Ollama at `http://127.0.0.1:11434/v1`, temperature 0, seed 1 when the server accepts it, `think: false` / Hermes `reasoning_effort: none`, per-task wall timeout 180s, and at most 6 tool rounds.

- **Hermes.** Pinned source checkout under `./tmp/hermes-agent`, driven by `AIAgent.run_conversation` (`examples/hermes-bakeoff/hermes_arm.py`). `HERMES_HOME` is `./tmp/hermes-home`. The runner refuses to start if `HERMES_HOME` is unset or resolves under `~/.hermes`.
- **Current pfy local path.** `./pfy` attach for `opencode` execs the `opencode` binary with `OPENAI_BASE_URL` set to the detected local engine. It is not itself a headless tool loop. The primary baseline attempted here is `opencode run` when that can be pointed at Ollama and this MCP server without writing `~/.config/opencode`. If that cannot be driven inside the turn cap, the arm is the direct OpenAI-compatible loop in `baseline_arm.py` (`POST /v1/chat/completions` with `tools=`). The results file names which one ran.

`num_ctx` starts at 32768 for both. Hermes refuses tool use below 64,000 tokens (`MINIMUM_CONTEXT_LENGTH` at the pinned checkout). When the probe returns that refusal, both arms move to 65536. The chosen value is recorded in the results.

## Tools

One stdlib MCP stdio server, `mcp_server.py`, is the only tool surface. It is read-only and fixture-backed. Every `tools/call` is appended to a JSONL log with the arguments and whether they validated. Schema-invalid calls come back as `isError` and count as invalid attempts, not successes.

Hermes shows the model `mcp__bakeoff__<tool>`. `opencode run` shows `bakeoff_<tool>`. Both clients call the server with the short name. Tools: `submit_choice`, `catalog_lookup`, `tools_query`, `bench_receipt`, `compute_sum`, `submit_answer`.

## Task set

`data/decision-gates/hermes-bakeoff.tasks.v0.json` is generated by `make_tasks.py` from labels that were fixed before either arm ran.

- 14 Choice cases copied from `laya-trial.cases.v0.json`, spread across families. The answer is a `submit_choice` call. Free text does not count.
- 8 fetch tasks and 2 two-step chains (lookup, `compute_sum`, `submit_answer`) against `sources/entries/`, `data/tools.json`, and the committed local-bench / atg receipts.
- 3 negatives. They pass only with zero tool calls and the expected text (a digit, a refusal, or the word in the prompt).

## Metrics

Computed from the server log and the client transcript. A sentence that names a tool is not a call.

- **valid tool-call rate** = schema-valid server calls ÷ structured attempts against these bake-off tools. An attempt is a server `tools/call` row, plus a client-side call of one of these tools that never reached the server. Hermes `tool_search`, `tool_describe`, and the `tool_call` envelope are meta calls. They are counted separately and are not attempts.
- **task success** = oracle pass ÷ tasks. The required tool names and arguments must appear on schema-valid calls, and the final `submit_*` value must match. Negatives pass only with zero calls and the expected text.
- **narrate-instead-of-call rate** = tasks whose assistant text contains a tool name, a fenced JSON call, or "I would call…", and for which no structured call reached the server, ÷ tasks that required a call.
- **latency** = per-task wall clock. Report p50, p95, and mean. Time-to-first-tool-call is the first server-log timestamp minus process start. The log stamp is UTC ISO-8601 with milliseconds (`2026-10-20T23:41:46.123Z`). A whole-second stamp is rejected, so TTFT is not rounded to `42.00`.
- **agent peak RSS** = max of process-tree VmHWM and summed VmRSS, sampled every 0.5s. Ollama RSS is recorded separately and is not part of either agent's peak.
- **thinking** is the same on both arms. A local proxy in front of Ollama forces `think: false`, `temperature: 0`, `seed: 1`, and `reasoning_effort: none` on chat requests. The proxy log stores those fields and not the prompt. Hermes `tools.tool_search.enabled` is `off`, so `tool_search`, `tool_describe`, and the `tool_call` batch tool are not offered.

## Clear-margin rule

Hermes **WINS** only when all of these hold. Otherwise **NO-WIN**, and the results name the failed condition.

- task success ≥ +10 percentage points over the baseline
- valid tool-call rate not worse by more than 2 percentage points
- narrate rate not worse by more than 2 percentage points
- p50 latency ≤ 1.5× the baseline
- Hermes agent peak RSS ≤ 2 GiB

Also report a Wilson 95% interval on each arm's task success. If the intervals overlap, say so.

## How this fails / how we recover

| Risk | How it fails | Recovery |
|------|----------------|----------|
| Ollama down or tag missing | A run would sit until timeout and look like a model failure | `--check` exits 2 with `FAIL` and does not load a model |
| Schema-invalid args counted as success | A bad call still "did something" | Server logs `schema_valid: false` and returns `isError`. The scorer does not pass the task on that call |
| Narrated JSON counted as a call | The model prints a fence and the oracle trusts prose | Narrate is true only when the server log has no call. A real server call is not narrate |
| Right tool, wrong args | The tool ran, so the task looks done | Oracle requires the labeled arguments. Wrong args fail. A matching call still passes |
| Scattershot choices | One correct `submit_choice` hides other guesses | More than one distinct choice fails, even when one equals the label. The same choice twice is a retry |
| Stale fetch or chain label | The model copies a drifted label and looks correct | The scorer recomputes the fixture. Disagreement is `oracle drift` and fails closed |
| Prefixed tool names | Hermes logs `mcp__bakeoff__*` and opencode logs `bakeoff_*` | Both prefixes are stored and scored as the short server name |
| Rescore needs `./tmp` transcripts | A checkout without the old work dir cannot be scored | `--rescore` uses the committed results JSON and the task file only |
| Margin just under +10 pp | A small edge is written up as a win | The rule is `>= +10 pp`. Just under is NO-WIN |
| Hermes reads `~/.hermes` | Mark's home config or keys enter the run | The guard exits before import if `HERMES_HOME` is unset or under `~/.hermes` |
| Context windows differ | One arm is faster because it saw less context | A refusal below 64k moves **both** arms to 65536 |
| Agent RSS includes Ollama | The 22 GB model fails the 2 GiB gate | The sampler skips processes whose command is Ollama |

## Run

Offline, no Ollama:

```bash
python3 examples/hermes-bakeoff/run.py --check --base-url http://127.0.0.1:9
python3 -m pytest tests/test_hermes_bakeoff.py -m "not live"
```

Live (loads `qwen3.6:35b`, sequential, unloads it at the end if this run loaded it):

```bash
python3 examples/hermes-bakeoff/run.py --live
```

Two tasks per arm, opted in:

```bash
HERMES_BAKEOFF_LIVE=1 python3 -m pytest tests/test_hermes_bakeoff.py -m live
```

Results: `pipelines/dogfood/hermes-bakeoff/results.json`. Write-up: `docs/eval/hermes-vs-current.md`.

Recompute that receipt without `./tmp` transcripts (stdout unless `--out` is some other path, so the published file is not overwritten):

```bash
python3 examples/hermes-bakeoff/run.py \
  --rescore pipelines/dogfood/hermes-bakeoff/results.json \
  --out pipelines/dogfood/hermes-bakeoff/results-rescored.json
```
